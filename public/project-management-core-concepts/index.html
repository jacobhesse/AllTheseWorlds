Project Management: Core Concepts & Formulas

A typical university PM course blends governance (charters/baselines), planning (scope, schedule, cost), execution and control (change, risk, quality), and delivery approaches (predictive, agile, hybrid). This page focuses on the concepts you apply repeatedly and the equations you compute on exams and in practice.

1) Foundations & Baselines

Core idea: project control is baseline management. You define what “success” means, you set baselines, you measure deviation, and you decide when/what to change (governance).

Constraints and the performance model

ConstraintOperational meaning
ScopeWhat is included/excluded; acceptance criteria; WBS boundaries.
ScheduleWhen outputs are delivered; dependencies; critical path and float.
CostBudget and funding; burn; forecasts; procurement commitments.
QualityFitness for use; defect rates; verification/validation plan.
RiskUncertainty that matters; threats/opportunities; reserves.
Baseline types (exam-friendly)

Scope baseline (scope statement + WBS + WBS dictionary), schedule baseline (approved model + dates), and cost baseline (time-phased budget). Change control governs modifications to these baselines.

2) Scope, WBS, & Estimating

The Work Breakdown Structure (WBS) is the backbone of predictive planning: it decomposes deliverables into manageable work packages that can be estimated, assigned, scheduled, and controlled.

Estimation accuracy concepts

  • Analogous (top-down): fast, less precise.
  • Parametric: uses rates (e.g., cost per unit) and drivers.
  • Bottom-up: slower, often more accurate when decomposition is strong.

Common “back-of-the-napkin” formulas

Effort (person-hours) = Work quantity / Productivity rate
Cost = Effort × Labor rate + Materials + Other direct costs
If your scope/WBS is wrong, your schedule and cost math will be precise but irrelevant. Most real project failures start upstream in scope clarity and assumptions.

3) Scheduling: CPM (Critical Path) & Float

Core CPM logic

CPM computes earliest and latest times across a dependency network. The critical path is the longest-duration path (zero total float) that determines the minimum project duration.

Forward pass (earliest times)

ES(activity) = max{ EF(predecessors) }
EF(activity) = ES(activity) + Duration(activity)

Backward pass (latest times)

LF(activity) = min{ LS(successors) }
LS(activity) = LF(activity) − Duration(activity)

Float (slack)

Total Float (TF) = LS − ES = LF − EF
Why CPM matters beyond exams

CPM is the foundation for schedule risk analysis, change impact analysis, critical chain discussions, and credible execution forecasts. Even agile programs often maintain a dependency network at the feature/release level.

4) Uncertainty: PERT & Probabilistic Thinking

PERT addresses uncertain durations by using three-point estimates and computing an expected value and variance. (This is a simplification, but it’s a standard intro tool.)

PERT expected duration

Expected time (te) = (O + 4M + P) / 6
O = optimistic, M = most likely, P = pessimistic

PERT activity variance (classic)

Variance (σ²) = ((P − O) / 6)²
Standard deviation (σ) = (P − O) / 6
Modern practice often uses Monte Carlo schedule risk analysis rather than “pure PERT,” but PERT teaches the key mental model: uncertainty is quantifiable and must be budgeted.

5) Cost Control: Earned Value Management (EVM)

EVM integrates scope, schedule, and cost by comparing what you planned to do (PV), what you actually accomplished (EV), and what you spent (AC).

Core EVM variables

PV (Planned Value) = budgeted cost of work scheduled
EV (Earned Value) = budgeted cost of work performed
AC (Actual Cost) = actual cost of work performed

Variances

CV (Cost Variance) = EV − AC
SV (Schedule Variance) = EV − PV

Performance indices

CPI (Cost Performance Index) = EV / AC
SPI (Schedule Performance Index) = EV / PV

Forecasting

BAC = Budget at Completion
EAC (simple) = BAC / CPI
ETC = EAC − AC
VAC = BAC − EAC

To-Complete Performance Index (TCPI)

TCPI (to meet BAC) = (BAC − EV) / (BAC − AC)
TCPI (to meet EAC) = (BAC − EV) / (EAC − AC)
Interpretation shortcuts

CPI < 1 → over budget for earned progress. SPI < 1 → behind schedule (in EV terms). Variances can be negative/positive; indices give normalized “how bad/how good.”

6) Risk: EMV, Expected Loss, Prioritization

Risk management formalizes uncertainty: identify, analyze (qual + quant), plan responses, monitor. Intro courses typically emphasize probability–impact thinking and decision analysis basics.

Expected Monetary Value (EMV)

EMV = Σ (Probability_i × Impact_i)

Risk exposure (simple)

Risk Exposure = Probability × Consequence
Decision tree expected value
Expected value at a decision node = max/min over alternatives of Σ (p × outcome)

Often used for make/buy decisions, response options, and evaluating whether mitigation cost is justified by expected loss reduction.

7) Communications & Stakeholders

Projects fail socially before they fail mathematically. Stakeholder alignment, decision rights, and information cadence are control mechanisms.

Communication channels (classic exam formula)

Channels = n(n − 1) / 2

Where n is the number of stakeholders/participants in a communication network. This models why coordination cost rises nonlinearly with team size.

8) Resources & Capacity

Resource planning translates scope into staffing, equipment, and constraints. The math is often simple; the challenge is constraints and contention.

Utilization and capacity (simple)

Utilization = Busy time / Available time
Capacity (per period) = Available hours × Productivity rate
Why “100% utilization” breaks projects

High utilization reduces flexibility, increases queueing delays, and amplifies variability. Many modern PMO operating models intentionally hold capacity buffers.

9) Agile/Lean Metrics & Flow

Modern courses increasingly include agile and hybrid delivery. While agile de-emphasizes upfront deterministic baselines, it still uses rigorous measurement—especially flow metrics.

Velocity (team-specific)

Velocity = Story points completed per iteration

Flow metrics

Throughput = Items completed per unit time
Cycle Time = Time from start to finish for an item
Lead Time = Time from request to delivery

Little’s Law (useful in Kanban/flow contexts)

WIP = Throughput × Cycle Time
If you control WIP, you can often control cycle time. This is one of the most practical “formulas” in modern delivery management.
